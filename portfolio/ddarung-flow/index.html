01 · 문제

지금 보이는 재고가 도착할 때도 남아 있을까?

대여 시점의 재고 정보만으로는 이동 후 도착할 시점의 대여 가능 여부를 알기 어렵습니다. 사용자가 필요한 수량과 도착 예상 시간을 기준으로 후보 대여소를 비교하도록 돕는 것이 프로젝트의 문제였습니다.

5주 동안 5명이 만든 팀 프로젝트입니다. 서비스는 예측 결과를 예약 보장으로 표현하지 않고 현재 재고·거리·이동시간과 함께 보여줍니다.

03 · 데이터 수집과 품질

수집 결과와 다음 단계에서 쓸 수 있는 데이터를 구분

따릉이·날씨 API와 Airflow 실행 흐름을 연결하고 Raw → Quality → Curated 단계로 분리했습니다. 원본은 보존하고 품질 기준을 통과한 데이터만 후속 단계로 넘기도록 구성했습니다.

  • 정상 재고 0대는 유효한 관측으로 보존하고 누락·음수·파싱 오류는 구분
  • 재실행 때 중복이 생기지 않도록 처리하고 timeout·실패 경계 확인
  • OCI Object Storage에 manifest·lineage·checksum을 대조하고 행 보존 및 immutable upload 확인
  • 원격 객체는 169개 HEAD metadata와 본문 표본 2개를 read-back 검증

프로젝트 전체의 과거 재고 6,152,132행 검사와 월별 최저 대여소 ID 결합률 99.6427%는 팀 검증치입니다. 개인 성과나 현재 운영 지표가 아닙니다.
